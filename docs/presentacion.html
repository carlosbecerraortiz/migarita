1 Arquitectura y Design for Testability

Separamos la lógica para poder probarla

Antes todo vivía en los controladores. Ahora cada capa tiene una sola responsabilidad y sus dependencias se inyectan.

✗ Antes: código acoplado

  • Validaciones y reglas mezcladas con $_POST, header() y exit
  • Los controladores hacían new ClienteModel() por dentro
  • Database siempre se conectaba a MySQL y hacía die() al fallar
  • EmailService creaba PHPMailer y leía la configuración él mismo
  • Imposible probar sin navegador, base de datos real y servidor de correo

✓ Después: capas e inyección de dependencias

Controladoresdelgados: request → servicio → redirección
▼
ServiciosClienteService, MovimientoService, UsuarioService, AuthService…
▼ dependencias por el constructor
Validadoresfunciones puras
Modelos + PDOinyectable

En las pruebas: la BD se reemplaza por SQLite en memoria y el correo por un mock. Mismas URL y mensajes de error que antes.

Refactorizaciones: (1) extracción de funciones puras a app/validators; (2) servicios en app/services que reciben los modelos y el EmailService por el constructor; (3) Database acepta un PDO inyectado o la variable MIGARITA_DB_DSN y lanza ConexionException en vez de die(); (4) EmailService recibe configuración y una fábrica de PHPMailer; (5) InformeService recibe la fecha de "hoy" para que las pruebas sean repetibles.

Todas las pruebas siguen el patrón AAA (Arrange, Act, Assert) y F.I.R.S.T.: cada prueba arranca con una BD nueva en memoria y no depende de las demás. Incluyen caminos felices, valores límite (abono igual al saldo vs. un peso más, contraseña de 5 vs. 6, monto 0 vs. 0,01, días en el borde del rango) y manejo de errores (SMTP caído, MySQL apagado).
3 Estrategia con Inteligencia Artificial

Claude Code generó, el equipo definió las reglas y auditó

Las aserciones verifican lo que el negocio exige, no lo que el código hacía.

Prompts reales
Tengo que añadir esto a mi proyecto… (+ guía del taller en PDF)
Usemos el código actual funcional de PHP para implementar todo lo de las pruebas
Sí, empieza con las pruebas

Reglas que le dimos al agente

  • No cambiar el comportamiento: mismas URL y códigos de error
  • AAA + F.I.R.S.T. y mocks obligatorios para BD y correo
  • Siempre valores límite: abono = saldo ✓, saldo + 1 ✗
  • Aserciones desde las reglas del negocio
